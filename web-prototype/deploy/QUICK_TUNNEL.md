# Windows 免费在线试用

双击项目根目录的 `start-web-trial.cmd`。启动器会检查当前 Python 虚拟环境、Node.js 与 Ollama，校验 Cloudflare 官方便携程序，构建页面并启动试用服务。首次使用会下载约 53 MB 的 `cloudflared.exe`，通过官方 GitHub 发行记录中的 SHA-256 校验后再运行。

启动成功后，窗口会显示一个 HTTPS 网址和本次访问码。将两项发给试用者，对方打开网址、输入访问码后即可上传资料、生成题目和答题。电脑需保持开机、联网，启动窗口需保持运行。Quick Tunnel 网址在重新启动后会变化，停止进程后原网址失效。[Cloudflare Quick Tunnel 说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

也可在项目根目录执行以下命令。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-web-trial.ps1
```

按 Ctrl+C 停止，或在另一个终端执行以下命令。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-web-trial.ps1 -Stop
```

启动器会通过 Windows 进程组管理自己启动的服务，关闭启动器时回收对应的子进程。检测到 Cloudflare 返回临时隧道失效时，会停止本次服务并提示重新启动。当前网址始终以 `current-trial.json` 和启动日志为准。

## 连接与数据

公开网址对应本机 `127.0.0.1:8093` 的独立试用入口，同一个入口提供构建后的页面与 `/api`。后台复用现有 Python 文件解析、OCR、千问出题、质检、归档和答题分析代码。模型由本机 `127.0.0.1:11434` 提供，SQLite 保存为本机文件。试用入口按本次准确的 HTTPS 域名验证 Host 和 Origin。

每个浏览器有独立的学习空间，通过 HttpOnly、Secure 和 SameSite Cookie 识别。每次启动生成新的访问码。Quick Tunnel 更换域名后浏览器会建立新的试用空间，旧空间的资料继续保存在本机，跨链接找回与账号同步需要后续开发。

程序与数据均位于 `web-prototype/.verification/quick-tunnel/`，该目录已被 Git 忽略。

- `current-trial.json` 记录本次网址和运行日志目录，服务停止后移除。
- `access-code.txt` 保存本次访问码，`session.key` 用于签名浏览器会话。
- `data/` 保存试用者的资料、题库和作答记录。
- `runs/` 保存每次导出的代码副本、页面构建、服务日志和隧道日志。
- `bin/` 保存官方便携程序及其版本、SHA-256 校验记录。

## 访问与上传限制

输入正确访问码后创建会话，同一来源地址十分钟最多尝试五次。默认最多 32 个浏览器空间，同一来源每小时最多创建六个空间。每个空间最多提交八次出题（包含重试），同一时间有一个排队或生成任务，最多创建 50 个知识库。后台按照单队列依次处理生成任务。

资料支持 DOCX、PDF、PNG、JPG、JPEG、BMP、WEBP 和 TXT。每次最多五份，单文件最多 20 MB，整个上传请求最多 25 MiB。接收过程会实际累计字节数，并限制同时接收的请求数量和单次等待时间。通过现有文件内容检查后才进入任务队列。

手机上传时会显示服务器已保存的数据量和速度。连接中断后会核对上传位置，再次提交相同资料和要求时复用原上传和任务。模型生成与质检继续使用后台任务。

网页试用现已改用每块最多 256 KiB 的分块上传。服务器确认收到的片段会保存位置，连接中断后重试同一片段不会重复写入。返回页面后会重试连接，刷新页面则恢复出题要求和知识库，再次选择相同文件即可续传。文件通过整份 SHA-256 校验后才创建原有出题任务。每个浏览器最多保留四份未完成上传，未完成片段保留二十四小时。旧的整文件接口继续供已有客户端使用。

续传已通过 23 项 Python 回归及客户端重试测试。公网实际上传一份 301,750 字节的测试 PDF，保存 131,072 字节后重建连接读取原进度，重复首块未增加文件长度，其余部分续传成功。并发完成请求只创建一个任务，实际千问生成、自动质检和答题均通过。记录在 `.verification/resume-result.json`。这项测试没有模拟手机操作系统的全部后台限制。

上传完成并创建任务后，模型出题独立在电脑后台运行。手机系统暂停后台浏览器时，网络上传也可能暂停，返回页面后通过续传恢复。Quick Tunnel 的网址失效仍需要重新启动，浏览器学习空间按域名和会话识别。

公开入口提供学习业务，诊断接口、接口文档、源文件目录和数据库目录不作为页面资源提供。服务内部健康检查使用独立探针。Ollama 和试用入口均绑定本机回环地址。

## 常见问题

启动失败时，查看窗口给出的本次 `runs/` 目录，优先阅读 `cloudflared.err.log` 与 `backend.err.log`。如果端口 8093 已被占用，可用 `-Port 8094` 启动。若检测到已有 Cloudflare 用户配置，启动器会提示处理，避免混用其他隧道。

Quick Tunnel 使用外部网络连接，移动网络的实际访问情况需要由试用者验证。它没有可用性保证，生成速度仍取决于本机模型、资料解析和排队情况。[官方限制说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

## 手机上传超时修复

手机截图中的 PDF 没有完整到达服务端。原浏览器上传等待上限和服务端总接收上限均为 120 秒，另有一次隧道连接中断记录。已延长上传等待、增加任务回执和并发去重，并修正上传中断时缺少响应造成的后台异常。21 项相关 Python 回归通过，前端已验证响应丢失后找回任务，以及再次点击时先核对而不重复上传。

隔离服务的慢速上传持续 129.3 秒后正常返回任务，公网短 PDF 的慢速上传持续 134.0 秒后正常返回任务，重复发送返回同一个任务标识。另用实际断开连接验证了后台不再出现缺少响应的异常。这些测试验证了接收和任务恢复机制，手机原始 PDF 的解析表现还需收到文件后再评估。

上一份已完成的 Word 任务中，正文提取约 0.1 秒，模型生成约 68.5 秒，批量复核约 32.8 秒。这个记录只能说明该 Word 任务的耗时分布，这份尚未到达的 PDF 仍需实际上传后评估解析表现。
