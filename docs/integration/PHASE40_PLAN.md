## 为什么要收敛

目前项目存在一条较长的Agent实验主链，和多个曾并行开发的草稿PR。通过单个分支CI，不等于并行分支各自的所有提交和文档已经进入最新候选。第39阶段已检查Web构建、59项Agent测试、85项后端质量测试、13项ZIP校验器测试、45项打包后API测试，并生成部署ZIP指纹；但这不是Docker实际启动或模型质量验收。

## 可安全执行的集成路径（需要审批）

1. **冻结候选**：记录代码head、main SHA、未完成人工审核事项与每条离机CI。
2. **审查主链功能**：先以已通过第39阶段统一测试的候选作为参考实现。不要直接把它的大量历史一次性合到main，应按功能拆分/审核并保留关键测试。
3. **处理侧链**：#16弱点Skill独立文档/CI差异，#18剩余源代码整理，#25 Android离机CI，#26/#27被移植功能的余下差异，#33项目衔接Skill，#34审计文档，#35独立回归测试。各项可选“独立保留/择优移植/合并/明确弃用”，但都需要有PR差异证据，不可一键关闭。
4. **统一CI入口**：第39阶段工作流当前绑定其阶段分支；在正式集成前应改成对**稳定集成候选/受保护分支**生效的长期工作流，且避免每个旧阶段的同类CI重复运行。尚未删除原阶段性工作流，避免失去既有历史验收入口。
5. **最终发布前确认**：Docker容器真实启动和healthcheck、真实Ollama/Qwen生成与人工核验、Android真机/模拟器交互、模型吞吐/资源约束、隐私与依赖版本审查。

## 离机集成门禁

在GitHub Actions或带完整Git历史的检出环境中执行：

```powershell
python -m pytest -q scripts/tests/test_integration_readiness.py
python scripts/check_integration_readiness.py --manifest docs/integration/phase40.json --output integration-audit.json
```

脚本只会检查提交祖先，报告仍分叉的侧链，并永远把 `shipReady` 保持为 `false`，直到人工验收和真实运行环境测试完成。它**不执行git merge、不改变PR目标分支或main**，也不检查两个分支语义功能是否完全相同。
