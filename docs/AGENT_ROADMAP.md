# 知学伴开发路线

## 当前优先事项

优先完成 Web 端功能测试与问题修复，用不同学科的自编资料验收学习闭环。Android UI 适配和真机测试暂缓。结果与未验证范围见 [Web 端功能测试报告](WEB_FUNCTIONAL_TEST_REPORT.md)。

知学伴以学习资料为输入，生成有原文依据的口诀和练习，保存作答记录并跟踪知识点掌握情况。求职作品重点展示如何让一条真实的 AI 业务流程可恢复、可验证、可维护。

目前已有 Android 客户端、Web 试用端、FastAPI 后台任务和本地 Ollama 推理。已验证若干资料解析、口诀生成、题目初筛与保存场景。下面的验收项需要独立验证，完成后再写入项目成果。

## P0  建立可复现的开发基线

- [x] **ZH-01 让新开发者能启动项目**。按 README 从干净检出启动本地 Web 和后台服务，用公开或自编的短文本完成一次资料到练习的演示。
  - 本地验收环境为 Windows、Python 3.12.3、Node.js 24.10.0 和 Ollama 0.40.16。前端按锁文件安装并构建，Python 在新建虚拟环境中按固定版本安装并通过 `pip check`。
  - SQL 短文端到端验收通过。实际调用 `qwen3:1.7b` 出题和复核，题目归档后可提交答案并生成知识点报告。第二个访客无法读取该任务、知识库或练习记录。完整的权限隔离验证仍见 ZH-04。
- [x] **ZH-02 设置 CI 和版本基线**。PR 自动检查前端构建、Python 接口和任务回归。至少记录一版测试通过的提交和启动环境。
  - [Web CI](../.github/workflows/web-ci.yml) 在 Windows 上使用 Node.js 24 和 Python 3.12 检查前端构建、Python 依赖和打包后的 Web API。真实模型生成沿用 ZH-01 的本机验收流程。
  - [首次 CI 基线](https://github.com/rxy5787-source/zhixueban-agent/actions/runs/43203257793) 对应提交 `48ae5bb`。运行器为 Windows Server 2025，Node.js 24.22.2，Python 3.12.10。前端构建、Python 依赖检查和后端打包通过，9 项接口测试全部通过。

## P1  验证任务可靠性和权限

- [x] **ZH-03 验证任务重启和重试**。覆盖排队、处理中、超时与取消。重启后能查询原任务，重试不会重复归档同一份结果。
  - 在 Windows 本机强制终止 Web 后端并用原数据目录重启。执行中的任务显示服务中断，排队任务沿用原 ID 继续处理。用延迟响应的测试服务验证了 HTTP 读超时。
  - 同一个任务的重复重试返回已有的重试任务 ID。如果这次尝试也失败，从新任务再次重试。回归测试覆盖并发请求、重复归档、取消子进程和保留已提交的处理进度。
  - 打包后的 Web API 共 13 项回归测试通过。用本机 `qwen3:1.7b` 和 SQL 短文复验出题、复核、归档与答题报告。
- [ ] **ZH-04 验证学习空间隔离**。用两个用户或试用会话测试越权读取资料、任务和练习记录，保留拒绝访问的回归用例。
- [ ] **ZH-05 建立分阶段日志**。按任务 ID 记录解析、OCR、推理、核对与归档的耗时和错误类别，日志避免记录私有文档正文和认证信息。

## P2  建立质量评测和单机容量基线

- [ ] **ZH-06 固定口诀和出题评测集**。从已有 20 条用例挑选可公开的测试资料，记录引用支持率、人工可用率和失败原因。比较改动前后的结果。
- [ ] **ZH-07 压测 1、3、5 个同时提交的任务**。分别记录排队时间、生成时间、内存峰值和失败数，依据结果写明演示环境的承载范围。

## P3  把流程演进为可控的 Agent

- [ ] **ZH-08 提取可验证的工具接口**。将资料解析、证据检索、生成、复核和归档建模为明确的步骤，定义输入输出、权限与失败结果。
- [ ] **ZH-09 加入有边界的任务路由**。按目标选择口诀、问答或练习流程，保存路由与工具调用记录。测试资料缺失、工具超时和步数超限场景。
- [ ] **ZH-10 完成作品展示**。准备一份架构说明、三分钟演示和一次真实失败的复盘，写清改动、指标、适用范围与仍待解决的问题。

建议按 P0 → P1 → P2 → P3 开发。每个 Issue 记录问题、验收步骤和证据。每次 PR 把改动关联到一个 Issue，方便回顾版本与效果。
