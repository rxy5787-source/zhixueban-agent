# Agent决策审计与离线回放（只读）

目标：解释知学伴Agent为什么选择某个已注册Skill、为什么停止，以及学习规划和异常恢复为什么给出特定建议。审计只涉及**确定性策略选择**，不允许将原文、题目或Qwen输出写进轨迹。

## 三类安全轨迹

1. `AgentRuntime.run().decisionTrace`：预算版本、每一步准备状态（是否已有资料/知识点/候选题）、已经接纳的**数量**、生成尝试次数、请求题数、选中的注册Skill、固定原因码、成功/失败/停止标识。
2. `StudyPlan.decision_trace`：学习证据是否完成分类、状态枚举 `needs_diagnosis`/`ready`/`no_weak_points`、弱点**数量**、下一个Skill与原因码。不包含知识点名称、成绩或用户身份。
3. `GET /api/generation-tasks/{task_id}/recovery-advice` 返回的 `decisionTrace`：受控的任务状态、失败类别、重试深度、是否已有重试、是否仍有来源资料、建议动作和原因码。该接口必须先验证浏览器会话及任务所有权。

## 回放规则

离线函数 `replay_runtime_trace`、`replay_study_trace`、`replay_recovery_trace` 对经过类型与字段白名单校验的记录进行重新决策，输出 `matched`、`divergentStep` 和固定错误枚举。整个回放过程**绝不执行Skill、写数据库、上传资料或请求模型**。

- 轨迹记录原策略版本，预算改变、被篡改的动作/原因码、无效特征和不完整终止事件都不能无条件判为通过。
- **新增连续性校验**：Agent的初始接纳数和尝试数必须为零；prepare、extract、generate、review只允许其声明的匿名状态变化，生成尝试数须恰好加一、已接纳数不能减少、请求题数不能中途变化；学习Planner的评估结果不能被后续规划步骤偷偷改写。违例返回固定原因码并标识出错步骤。
- 用匿名特征重新构造**最小化状态**。因此，匹配表示“当前策略在该匿名状态下会做出同样决策，而且相邻匿名状态满足声明的转换约束”，而不是证明用户真的具备这些状态，也不证明Qwen正确、事实依据真实或者轨迹从未被人为修改。攻击者如果能整体伪造一条自洽轨迹，本校验仍无法证明其真实性。
- 无持久化审计表；不增加日志对资料内容的泄露面。如未来需提供跨进程防篡改审计，应在授权、隐私和存储方案确认后增加带密钥的服务端签名与最小化保留策略，而不是直接上传原始轨迹到公共仓库。

## 安全与可复现测试

- 正常生成、首次质量不通过后再生成、达到预算停止、Skill报错。
- 三类学习方案：诊断练习、针对薄弱点练习、综合复习。
- 任务超时、来源不可读、视觉依据不足、质量审核、已存在重试、取消、成功及中断。
- 篡改动作、原因码、证据布尔值或预算能在回放中出现明确分歧。
- 注入模拟的隐私词句，确保轨迹中**不包含**学习资料、知识点名字、答案、Prompt、异常消息等。
- Web会话隔离继续通过原有API测试；审计回放不会绕过会话权限取得用户任务。

## 不涉及真机、真实Ollama或新的Skill

GitHub CI中的这些轨迹来自固定的Python模拟输入，不能当作Qwen实测准确率或真实设备日志；仍需后续人工质量审核、真实Ollama和Android真机验收。

当前审计只是确定性的代码决策与复算，没有新的独立Agent执行职责。**本阶段不新建Skill**。
