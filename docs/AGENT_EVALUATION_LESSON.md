# 第七关：Agent Evaluation — 真实执行指标与边界

本实验基于 [PR #20](https://github.com/rxy5787-source/zhixueban-agent/pull/20) 的用户确认出题Skill。**仅针对当前浏览器会话所属知识库中的 Agent 确认出题记录**进行聚合；普通手动出题不混入分母。尚未合并到主分支。

## 业务指标与分母

- **终态完成比例**：状态为 `succeeded` 或 `partial` 的任务数 / 最近抽样的终态任务数。取消、失败、中断均在终态分母中；排队中、运行中不在分母中。没有终态任务时值为 `null`。
- **自动初筛接纳比例**：具有有效 `generatedCandidates > 0` 和 `accepted <= generatedCandidates` 数据的任务中，自动接纳题数合计 / 已生成候选题合计。它**不是正确率、真实引用支持率或人工可用率**；样本不足时为 `null`。
- **拒绝记录分类**：统计任务结果中 `rejected` 条目的受控状态枚举数量；不返回理由原文，也不将拒绝条数视为候选题总数。
- **重试事件**：根据保存的 `job_events.stage` 记录 `根据质检原因重新生成` 的次数；不是模型API实际调用次数。
- **任务总耗时**：从任务创建到进入终态最后更新的墙钟时间（含排队与处理），**不是模型推理耗时**。没有终态时为 `null`。
- **学习策略**：在用户确认排队的事务中存储 `plan_action` 枚举（诊断、薄弱点练习、综合复习），而不是事后由提示词推断。旧记录迁移后标记 `unknown`。

## 接口与隐私

`GET /api/study-evaluation/{library_id}`

通过已有签名浏览器Cookie与Origin/Host保护；数据查询使用该会话专属 `TrialStore`。无会话401、非法ID422、其他空间或删除的知识库404。

仅返回任务ID、聚合数量、受控状态、毫秒耗时等。**不读取或返回** `model_call.response`、资料正文、题干、完整提示词、答案和质检拒绝理由。UI“学习分析”可展示执行评测概要，空样本明确展示“暂无可统计数据”。

## 已知不足

1. 本次**没有**跑20条人工标注题单；不能宣称事实正确率、引用真实性、人工可用率已经得到测量。
2. 现有事件表仅有阶段名称与事件时间；无法准确还原每一轮的模型token、推理耗时与费用。若后续要测，应增加独立的结构化阶段计时，不从阶段字符串猜测。
3. 统计只面向当前会话当前知识库**最近20条**已确认任务。少量试用样本不能推广为一般性能结论。
4. 旧 `study_practice_dispatches` 表会安全增加 `plan_action` 字段，原有幂等回执不删除。已有旧记录显示 `unknown`。

## 测试

新测试用固定**伪造任务记录**验证数学聚合、空样本、越权、匿名访问、敏感内容不泄露、迁移及只读性；这些是代码回归测试，**不是模型实验数据**。GitHub CI应分别运行Web构建、Agent单元测试和打包后Web API回归。

下一步应按ZH-06建立固定20条真实问答评测集，人工记录正确性、可溯源性与失败原因，再讨论真实内容质量和前后优化收益。
